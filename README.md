# CS 255 DriverPass Project

## Project Summary

The DriverPass project involved designing a system for a company that wanted to help students prepare for their driving tests. The client wanted a system that would allow students to access online practice tests, study materials, and schedule driving lessons. The system also needed to allow instructors to manage their schedules and administrators to manage student accounts and other information.

## What I Did Well

I think one part I did particularly well was identifying the different requirements of the system and organizing them into the design documents. I was able to break down the different functions and show how students, instructors, and administrators would interact with the system. Creating the UML diagrams also helped me understand how the different parts of the system would work together.

## What I Would Improve

If I could revise one part of my work, I would focus on improving the UML diagrams. Although the diagrams show how the system should function, I think I could make some of them easier to understand by organizing the information better. This would make it easier for someone reviewing the design to understand how the different parts of the system interact.

## Understanding User Needs

I interpreted the user's needs by reviewing the DriverPass interview and identifying what the client wanted the system to accomplish. I used this information to determine the different functions and requirements that needed to be included in the design. I think understanding the user's needs is important because the system needs to solve the problems the client is experiencing. Without understanding those needs, the finished system might not work the way the client expects.

## My Approach to Software Design

When designing software, I think it is important to understand the requirements before beginning the actual design. Breaking the system into smaller parts makes it easier to identify what each component needs to do and how everything works together. In the future, I would continue using techniques such as requirement analysis, UML diagrams, and project scheduling to help organize the development process. These techniques make it easier to identify potential problems and make changes before development begins.
